# 通用文件夹浏览器

Oyster 需要在应用内阅读由目录承载的内容：工作台中的 Artifact 和随应用发布的设计文档都需要文件树，但它们不因此成为同一种领域对象。

因此应用复用一个通用浏览器。调用方提供目录和界面语境，浏览器展示文件树，并按 Markdown、文本或暂不支持的二进制内容选择阅读方式；符号链接作为叶节点，不递归跟随。Markdown 相对链接和 wikilink 支持在当前浏览历史中继续导航。

浏览器只负责发现、读取和展示，不拥有文件、索引或编辑状态。工作台提供 Artifact 入口；设置提供设计文档入口。设计文档不会因此进入用户 Repository 或成为 Artifact。

## 信任与规模取舍

当前桌面应用采用高信任本机模型：文件操作接受调用方给出的绝对路径，Markdown 链接可以在文件系统语义下解析，不增加路径引用、allowlist、Workspace 或 Sandbox。调用方与浏览器的边界由 typed IPC 和当前 OS 用户权限承担。

目录树当前可以一次递归读取。这是早期简单性取舍；只有真实 Artifact 规模证明响应时间或内存不可接受时，再引入分页、延迟展开或索引。展示新格式时仍应保持文件发现与 Renderer 分离，而不提前建立插件体系。
