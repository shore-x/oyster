# UI 交互与视觉基础

## 体验原则

Oyster 采用对话优先、内容优先、低装饰和渐进披露的桌面界面。极简意味着减少同一时刻的装饰与决策，不意味着隐藏身份、结果、错误、当前动作或完成任务所需的操作。

对话是主要协作入口；知识库、工作台、数据来源、Skills、知识加工和设置是稳定产品工作面。界面层级不机械复制内部对象层级，文件浏览和对象详情不需要独立一级导航。

## 详情与导航

同一工作面中的补充信息优先使用折叠、Tab、主从分栏或非模态 Inspector：

- 摘要本身要能说明对象身份和关键状态；
- Tab 只切换共享上下文中的同级工作面；
- 需要持续选择并阅读时使用稳定主从分栏；
- Inspector 展示不应打断主任务的上下文详情，并保留明确关闭与键盘操作；
- Modal 只用于必须先处理才能继续的确认或阻塞状态。

普通阅读不创建“列表—详情—返回”的额外业务导航，也不层叠多个 Inspector。

## 布局与滚动

App Shell 拥有视口，业务页面自行声明自然流式布局或填满剩余空间的工作区布局。每个可见区域只有一个明确的纵向滚动所有者；稳定列表、正文、输入和 Inspector 可以分别滚动，但不能依赖 document scroll 或用固定视口减法猜测剩余高度。

输入框、页面级操作和对话 Composer 应保持可达。切换一级工作面不应无故销毁仍在运行的状态。

## 语言

UI 语言只决定产品文案、locale 与可访问性属性。Agent 回复和 Repository 自然语言是独立设置，在新的 Invocation 中生效；切换任一设置都不改写用户输入、既有内容、引用原文或 Debug Record。

## 视觉语言

文字、留白和稳定阅读顺序承担主要层级；背景、边框、圆角和阴影只表达真实交互或区域边界。Renderer 的语义 token 是公共视觉值入口，业务组件不自行复制相近的字号、颜色、圆角或阴影体系。

正文应易读，普通文字保持足够对比度，焦点和可访问名称不可因视觉简化而丢失。常规 Surface 不依靠阴影堆叠层级，Overlay 使用统一视觉语言。

具体 token 值、组件类名、窗口尺寸和 smoke 场景由共享 UI 代码、静态检查与测试维护。设计评审以本页原则为准，发现页面实现漂移时修复共享层或业务样式，而不是在文档中复制新的常量表。
