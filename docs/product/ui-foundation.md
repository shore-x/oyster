# UI 视觉基础与渐进披露

> 状态：当前实现规格
>
> 日期：2026-08-04
>
> 范围：规定 Oyster Renderer 的稳定视觉语言、信息层级和详情披露方式；不规定具体业务页面的数据模型或工作流。

## 1. 目标风格

Oyster 采用**内容优先、低装饰、渐进披露**的产品界面。文字、留白和稳定的阅读顺序负责主要层级；背景、边框和形状只用于区分交互边界、状态或真正独立的区域，不用来装饰每一块信息。

界面默认先展示完成识别和选择所需的摘要。只有部分用户或部分时刻需要的信息放入统一的详情披露控件；完成当前任务必需的主要操作、错误和状态不能被隐藏。展开只改变展示量，不改变底层数据所有权或业务状态。

## 2. 统一视觉模块

`src/renderer/src/ui/tokens.css` 是 Renderer 视觉值的唯一公共入口。业务样式使用语义 token，不自行创建相近的字号、字重、灰色、圆角或阴影层级。

- 字体使用平台 `system-ui`，并显式提供 macOS、Windows 与简体中文回退；不声明未随应用分发的字体为首选字体；
- 阅读正文为 15px，常规交互和列表标题为 13px，标签为 12px，只有元信息使用 11px；长文本使用 1.75 行高；
- 默认字重保持在 400–500，只有需要脱离正文快速定位的标记使用 600；标题不使用压缩字距，清晰度主要由更深的文字颜色提供；
- 普通文字在白色背景上至少满足 4.5:1 对比度。`text-muted` 仍是可读文字，禁用态才使用更弱的 `text-disabled`；
- 常规 Surface 不使用阴影。Overlay 可以使用一个统一阴影；圆角只保留 control、surface、overlay 和 pill 四种语义；
- App 主背景与内容背景为白色，侧栏和次要分组只使用接近白色的中性 Surface。

`src/renderer/src/ui/disclosure.css` 定义统一的摘要—详情交互。摘要必须能独立说明条目身份和当前关键状态；展开内容可以包含完整正文、参数、调试输出和次要操作。

## 3. 验证要求

- CSS 中的像素字号和数字字重只在视觉 token 模块中定义；
- 具体业务页面的展示形态由各自产品规格定义，不把阶段性页面方案写入本视觉基础；
- Electron UI smoke 验证主要摘要默认可见、展开后信息仍完整、页面无水平溢出；
- 视觉检查至少覆盖 900px 与 1160px 窗口，确认放大文字不会被固定高度裁切。
